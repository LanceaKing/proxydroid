# TLS 后端实测与选型建议（2026-11-19）

建议将 **BoringSSL 作为本项目下一步性能优先的通用选型**：在本次固定条件下，24 组短连接场景的五轮 RPS 中位数均领先，完整握手也更省 CPU。**长连接持续转发和引擎体积优先时，选择 wolfSSL ARM 变体**：24 组转发场景的吞吐中位数和 CPU/GiB 均更好。这个建议不构成所有平台、流量类型的统一排名。

**选型落地（2026-11-19）：用户已采纳 BoringSSL，Gradle、根 CMake 和 APK 校验的默认后端已同步切换。** 以下性能数据来自切换前冻结的同机实验；实验期间发布默认是 OpenSSL 3.5.9，原始样本和统计数据保持不变。安装后的实际应用路由、系统信任与 API 19 运行验收仍需单独完成，并持续承担固定提交升级时的 API 适配成本。wolfSSL 的 TLS 1.2 小请求额外延迟已单独做 socket 选项诊断，不能直接归因于密码算法。

这是用户改为同一台设备后的 **IPv4 回环**实验，不是 LAN 结果。原 LAN 的纯 TCP 对照也出现过 64 并发超时，因此没有将那些数据并入结论。

## 测试条件与有效性

- 主矩阵时段：2026-11-19 00:45:24–09:34:37（Asia/Shanghai）。
- Pixel 5，Android 14，arm64-v8a，`127.0.0.1:8888`；固定 OpenSSL 3.5.9 参考服务。
- NDK 25.1.8937393、CMake 3.22.1、Android API 21 原生构建、`RelWithDebInfo`。三后端使用同一工具链和共有工作负载参数。
- 引擎/独立 TLS harness 固定 CPU 5（`20`），负载发生器固定 CPU 4（`10`），参考服务固定 CPU 0–3（`f`）。已实查线程 affinity；未设置独占 CPU，CPU 6–7 未分配给基准角色。
- 使用自然冷却，保留 `schedutil`，未锁频或更改充电设置。主矩阵前后电池温度为 33.6/34.0 °C、USB 供电，电量 98%/95%。这些不是所有样本的温度或频率保证。
- 相同 RSA-2048 证书、CA；独立握手 harness 使用 X25519。转发保留各后端真实 ClientHello，因而包含当前集成行为差异。
- TLS 1.2/1.3 × AES-128-GCM/ChaCha20-Poly1305 × none/NTLM × 并发 1/16/64；完整握手和恢复只测 none、并发 1。
- 每组合 5 个有效轮次，后端顺序逐轮轮换。短请求和持续转发：预热 10 秒、测量 30 秒；独立握手/恢复：预热实际为 20 次，测量 200 次，不将其描述为各运行 10/30 秒。
- 每流 256 KiB 未回显窗口、10 秒 inactivity timeout 保持不变。短请求每次建立新连接并逐字节核对 4096 B 回显；持续转发停止发送后排空并核对全部字节。
- 每个有效样本测量前后 thermal status 都必须为 0；热拒绝保留记录，自然冷却后重试。计时、窗口、错误处理和温控阈值没有放宽。

表中默认统计量为**每组合五轮中位数**；`[min, max]` 是五个有效轮次的观测范围，不是置信区间。P50/P95 是**每轮分位数的五轮中位数**，没有合并全部请求重新计算。相对百分比取同轮配对比值的中位数，因此可能不同于两个中位数相除。完整 168 行及所有区间见 [CSV](tls-backend-comparison-20261119.csv)。

| BoringSSL | ebd922adc708 | 2,387,336 | 2.277 |
| wolfSSL ARM | 5.9.4 | 1,527,208 | 1.456 |

BoringSSL 固定提交 `ebd922adc708a48b0cccfcdf81e854a3fdc1b7b6`；wolfSSL 固定提交 `3c5eead44904df64e6a5a1f4ebdce377d35a849a`。体积使用同一种剥离方式，仅代表 arm64 引擎，不是 release APK 增量。

wolfSSL 为单独缓存的实验 ARM 变体：`WOLFSSL_ARM_ASM=yes`、`WOLFSSL_GEMATH=yes`，C/ASM 定义为 `WOLFSSL_ARMASM`、`WOLFSSL_AARCH64_NO_SQRDMLSH`，ASM 增加 `-march=armv8-a+crypto`。`WOLFSSL_SP_MATH_ALL=yes`，未另启用 SP ARM64 优化，不能声称已经测到所有 wolfSSL 优化的上限。发布配置未变。

三个实际引擎二进制均含 AES、PMULL、SHA256 指令；wolfSSL 的运行时 CPU probe 也检出这些能力。针对这份 ARM 库的 wolfCrypt 向量集在设备上 exit 0。更早向量运行的失败来自测试夹具证书绝对路径，使用 `CERT_REL_PREFIX="./"` 后通过；没有把失败记录当成算法错误。

## TCP_NODELAY 独立诊断

主矩阵和独立审计结束后，使用原封不动的 driver、引擎及参考二进制，通过 `LD_PRELOAD` 的 `connect` hook 做开关对照。两轮后端顺序和选项顺序交替；每组预热 1 秒、测量 3 秒，AES/none/c1，温控仍要求测量前后为 0。

共 24 个有效诊断样本。日志通过 PID/PPID 确认是引擎子进程的上游 socket：控制组 `TCP_NODELAY=0`，强制组实际从 0 变为 1，`setsockopt` 成功；驱动本来已为 1。参考服务没有加载 hook。**以下是因果诊断 smoke，未并入或替换 840 个比较样本，不能用其三秒 RPS 重新排名。**

| TLS | 后端 | 原选项 P50 ms | NODELAY=1 P50 ms | 减少 ms |
| --- | --- | --- | --- | --- |
| 1.2 | OpenSSL | 19.190 | 19.017 | 0.173 |
| 1.2 | BoringSSL | 17.249 | 16.773 | 0.476 |
| 1.2 | wolfSSL ARM | 59.055 | 16.991 | 42.065 |
| 1.3 | OpenSSL | 18.568 | 18.554 | 0.014 |
| 1.3 | BoringSSL | 16.593 | 16.560 | 0.032 |
| 1.3 | wolfSSL ARM | 17.571 | 17.443 | 0.127 |

在所测 AES/none/c1 条件下，wolfSSL TLS 1.2 的约 40 ms 额外延迟在强制 NODELAY 后消失，TLS 1.3 与另两个后端没有相同量级的变化。这支持当前引擎上游 socket 的 Nagle/延迟 ACK 交互是该额外等待的主要来源；没有抓取逐包证据，不能进一步指定触发它的某条 TLS record/ACK。它不代表 wolfSSL 密码算法慢 40 ms，其他认证和并发条件需在修复时验证。

本轮没有修改产品 socket 行为。若采用 wolfSSL，应把这个传输行为作为后续独立修复并做完整回归；修复前后的正式比较需要使用一致的新构建和完整测试条件重新运行。

## 对照、参考端负载与边界

绕过引擎/TLS 的纯 TCP 对照，仍采用同样 30/10 秒、256 KiB 窗口及 10 秒超时；每个格子只有一个有效控制样本：

| 16 | 2922.44 | 2946.61 | +0.83% |
| 64 | 2681.81 | 2920.15 | +8.89% |

参考服务按进程 CPU 时间/实际采样间隔折算的核数如下；它分配 4 核。范围来自该模式全部有效样本，跨越不同 TLS/认证/并发条件，不能当作单组合波动。

| 模式 | 参考端核数中位数 | 核数范围 | 所分配 4 核占用中位数 |
| --- | --- | --- | --- |
| handshake | 0.677 | [0.606, 0.726] | 16.9% |
| resume | 0.419 | [0.335, 0.541] | 10.5% |
| short | 1.562 | [0.193, 2.188] | 39.1% |

TCP 对照说明本次回环路径没有重现旧 LAN 的连接超时，不能证明参考端 TLS/RSA 容量无限。平均汇总 CPU 占用仍不能排除参考服务某个线程、瞬间、锁或调度的限制；因此这些吞吐是**固定 CPU 分配下整条回环路径的实测**，不是已证实的纯客户端库极限。

结论还受未锁频、共享 DVFS/缓存/内存与温控采样粒度影响；CPU 亲和性和轮换顺序只能减少部分干扰。没有测试大核峰值、其他 SoC/ABI、独立 LAN、真实公网 RTT/丢包、其他密钥/密码组合、真实应用路由、API 19 运行或电池能耗。较低 CPU/字节不等同于已测得更省电。

## 维护与落地建议

1. **通用性能选型：BoringSSL。** 本次短连接和完整握手优势稳定，arm64 引擎也从 5.289 MiB 降至 2.277 MiB。固定提交、统一兼容层和三后端 CI 必须随升级维护；官方不保证 API/ABI 稳定，也不推荐将其视为通用 OpenSSL 的无成本替代。
2. **持续传输或体积优先：wolfSSL ARM。** 本次 24 组转发中位数领先，体积为 1.456 MiB。先处理并回归上面的 TLS 1.2 socket 选项问题，并把 ARM 优化配置作为明确的受支持构建变体验证其他 ABI。项目 README 声明 GPLv3；wolfSSL 提供 GPLv3/商业双许可，不能仅以“必须付费”为由排除。
3. **OpenSSL 保留为显式可选后端。** 用户已决定将默认构建切换到本次锁定提交的 BoringSSL；OpenSSL 3.5 是支持至 2030-04-08 的 LTS，仍可用于重视稳定公开接口和长期维护的构建。构建选型变更不等同于完成上述安装、应用流量和最低 Android 版本验收。

官方维护资料在 2026-11-19 重新获取核对：[OpenSSL 发布策略](https://openssl-library.org/policies/releasestrat/)、[锁定提交的 BoringSSL README](https://github.com/google/boringssl/blob/ebd922adc708a48b0cccfcdf81e854a3fdc1b7b6/README.md)、[wolfSSL 许可说明](https://www.wolfssl.com/license/)。本地副本及 SHA-256 见 `build/tls-loopback-20261118/official-sources-20261119.json`。
